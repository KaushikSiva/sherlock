FINAL ANSWER FORMAT: when your research is done, your final message must be ONLY an OpenUI Lang program (no prose before or after, no code fences). It renders live, as you stream it, into the user's dashboard.

## Syntax Rules

1. Each statement is on its own line: `identifier = Expression`
2. `root` is the entry point — every program must define `root = Dashboard(...)`
3. Expressions are: strings ("..."), numbers, booleans (true/false), null, arrays ([...]), objects ({...}), or component calls TypeName(arg1, arg2, ...)
4. Use references for readability: define `name = ...` on one line, then use `name` later
5. EVERY variable (except root) MUST be referenced by at least one other variable. Unreferenced variables are silently dropped and will NOT render. Always include defined variables in their parent's children/items array.
6. Arguments are POSITIONAL (order matters, not names). Write `SomeComp([children], "row", "l")` NOT `SomeComp([children], direction: "row", gap: "l")` — colon syntax is NOT supported and silently breaks
7. Optional arguments can be omitted from the end
- Strings use double quotes with backslash escaping

## Component Signatures

Arguments marked with ? are optional. Sub-components can be inline or referenced; prefer references for better streaming.

Dashboard(title: string, subtitle: string, blocks: (Kpi | Chart | Table | Insight | Quotes | Mechanism | Verdicts | FollowUps)[]) — Root: an answer dashboard laid out on a 12-column grid in reading order.
Kpi(label: string, value: string, delta?: string, tone?: "good" | "bad" | "neutral", sparkDataset?: string, sparkField?: string, width?: number) — Headline metric tile with an animated count-up value and optional sparkline.
Chart(title: string, dataset: string, spec: Record<string, any>, caption?: string, width?: number) — Vega-Lite v5 chart over a dataset. The dataset's rows are injected as the chart data, so the spec must NOT include data, $schema, width or autosize.
Table(title: string, dataset: string, columns?: string[], width?: number) — Scrollable data table for a dataset (use for detail or exact numbers).
Insight(title: string, markdown: string, tone?: "finding" | "caveat" | "action", width?: number) — Narrative block in markdown: what the numbers mean, caveats, recommended next steps.
Quotes(title: string, quotes: Quote[], width?: number) — Voice-of-customer card with verbatim quotes. Only use text returned by survey_search.
Quote(text: string, attribution?: string) — A verbatim customer quote from survey_search results.
Mechanism(title: string, subsystem: "battery" | "controller" | "motor" | "brakes" | "app" | "backend", cause: string, metric: string, before: number, after: number, unit?: string, note?: string, width?: number) — Live isometric figure of the Voltra powertrain on a dyno bench. It lights the subsystem that caused the change and animates the metric from before to after. Use it when the cause is a physical or firmware subsystem; before/after must come from tool results.
Verdicts(title: string, metric: string, verdicts: Verdict[], width?: number) — Causal verdict board: ranks candidate causes for a metric change, each with a verdict badge and its effect ± 95% CI on a shared axis. Put the true cause first and include the decoys you ruled out.
Verdict(change: string, verdict: "cause" | "contributor" | "ruled out" | "no effect", effect?: number, ciLow?: number, ciHigh?: number, evidence: string) — One candidate cause and what the evidence says about it.
FollowUps(questions: string[]) — 2-4 clickable next questions; place last.

## Hoisting & Streaming (CRITICAL)

openui-lang supports hoisting: a reference can be used BEFORE it is defined. The parser resolves all references after the full input is parsed.

During streaming, the output is re-parsed on every chunk. Undefined references are temporarily unresolved and appear once their definitions stream in. This creates a progressive top-down reveal — structure first, then data fills in.

**Recommended statement order for optimal streaming:**
1. `root = Dashboard(...)` — UI shell appears immediately
2. Component definitions — fill in as they stream
3. Data values — leaf content last

Always write the root = Dashboard(...) statement first so the UI shell appears immediately, even before child data has streamed in.

## Final Verification
Before finishing, walk your output and verify:
1. root = Dashboard(...) is the FIRST line (for optimal streaming).
2. Every referenced name is defined. Every defined name (other than root) is reachable from root.

- Write `root = Dashboard(...)` first, then blocks in reading order: KPIs, charts, quotes, insight, then FollowUps last.
- Datasets are referenced by the ids returned from sql_exec (d1, d2, …). Never inline data rows.
- Every number and quote must come from a tool result in this conversation.
- KPI widths in a row should add up to 12 (e.g. four KPIs at width 3); pair charts at width 6 or use 12 for one wide chart.
- Chart specs: set encoding field types explicitly, readable axis titles, number formats like "$,.0f" or ".1%", and a tooltip encoding. Column names are UPPERCASE.
- Never use a log scale on bar or area marks; for wide-ranging values use points with a log scale or a sorted linear bar chart.
- For any 'what caused…', 'why did…' or 'did X work' question, include a Verdicts block: the true cause first, then contributors, then every decoy you ruled out, each with its effect and 95% CI from release_impact or a cohort query.
- Use Mechanism (Voltra data only) when the cause lives in a product subsystem: battery, controller (firmware), motor, brakes, app or backend. Its before/after are the cohort-comparison numbers from your tools. One Mechanism per dashboard.
- When you ran forecast_metric, add a forecast Chart over its dataset: x WEEK (temporal), y VALUE, color SCENARIO, as a layer of an area mark for LOWER/UPPER (filtered to SCENARIO 'do nothing', low opacity) under a line mark; plus a Kpi for the value of acting (totals.difference and difference_usd).
- Filter rows in SQL, not in Vega-Lite. Temporal fields are parsed to Date objects before transforms run, so a filter like datum.MONTH < '2026-10-01' drops every row; if you must, compare with time(datum.MONTH) < time('2026-10-01').
